# Домашнее задание к занятию 17 «Инцидент-менеджмент»

### Задание 1. Постмортем сбоя инфраструктуры баз данных GitHub (21-22 октября 2018 г.)

#### 1. Summary
21 октября 2018 года в 22:52 UTC сервис GitHub столкнулся с масштабным сбоем в работе СУБД. Инцидент привел к деградации платформы на 24 часа 11 минут. Пользователи наблюдали рассинхронизацию интерфейса - тикеты, пулл-реквесты и комментарии временно пропадали. Доставка вебхуков и публикация GitHub Pages были заморожены. Непосредственные Git-хранилища не пострадали. Потери пользовательских данных не произошло.

* **Дата и время начала:** 21 октября 2018 г., 22:52 UTC.
* **Дата и время завершения:** 22 октября 2018 г., 23:03 UTC.
* **Общее время деградации сервиса (TTR):** 24 часа 11 минут.
* **Критичность инцидента:** Severity 1 (Critical).

---

#### 2. Impact
* **Пользовательский интерфейс:** Веб-интерфейс отдавал устаревшие метаданные. Записи создавались, но после перезагрузки страниц не отображались.
* **Интеграции:** Приостановлена обработка очереди вебхуков. В очереди скопилось свыше 5 миллионов событий. Около 200 тысяч событий было сброшено из-за истечения внутреннего TTL.
* **Сервисы:** Остановлены сборка и деплой GitHub Pages (бэклог составил более 80 тысяч билдов).
* **Git-операции:** Базовые операции с кодом (clone, fetch, push) работали штатно. Git-репозитории размещены на отдельных шардах и сбоем затронуты не были.

---

#### 3. Timeline

* **21.10.2018 22:52 UTC** - Плановые работы по замене оптоволоконного 100G-оборудования вызвали потерю связи между сетевым хабом и основным дата-центром (ЦОД US East Coast). Связь прервалась на 43 секунды.
* **21.10.2018 22:52:43 UTC** - Кластер Orchestrator потерял лидера по Raft-консенсусу в ЦОД East Coast. Узлы на Западном побережье (US West Coast) и в облаке сформировали кворум. Orchestrator автоматически назначил базы West Coast в роли primary и перестроил топологию.
* **21.10.2018 22:54 UTC** - Системы мониторинга зафиксировали шквал алертов. Приложения начали направлять запросы на запись через всю страну с огромной задержкой.
* **21.10.2018 23:02 UTC** - Инженеры выявили рассинхронизацию топологии репликации. За секунды сетевого сплита на East Coast успели пройти транзакции, не дошедшие до West Coast. Возник риск split-brain.
* **21.10.2018 23:07 UTC** - Заблокирован инструмент деплоя. Статус сайта переведен в желтый, затем в красный (23:13 UTC).
* **21.10.2018 23:19 UTC** - Для сохранения целостности данных принято решение отключить фоновые задачи - вебхуки и GitHub Pages.
* **22.10.2018 00:05 UTC** - Сформирован план восстановления - восстановить базы из бэкапов на East Coast, догнать репликацию с West Coast и провести контролируемый failover.
* **22.10.2018 06:51 UTC** - Часть кластеров восстановилась из удаленных бэкапов. Скорость восстановления через публичное облако оказалась низкой. Принято решение синхронизировать оставшиеся базы напрямую с узлов West Coast.
* **22.10.2018 11:12 UTC** - Роли primary возвращены на East Coast. Задержка записи спала. Реплики чтения отставали на несколько часов. Нагрузка выросла из-за начала рабочего дня в Европе и США.
* **22.10.2018 13:15 UTC** - Начало пикового трафика. Отставание репликации перестало сокращаться. Подняты дополнительные read-реплики в облаке East Coast для разгрузки кластера.
* **22.10.2018 16:24 UTC** - Реплики синхронизированы. Выполнен возврат к исходной рабочей топологии. Начата разборка скопившегося бэклога.
* **22.10.2018 16:45 UTC** - Обнаружен сброс ~200 000 вебхуков по TTL. Выкачен хотфикс с увеличением времени жизни пакетов.
* **22.10.2018 23:03 UTC** - Бэклог вебхуков и билдов полностью разобран. Системы работают штатно. Статус переведен в зеленый.

---

#### 4. Root Cause Analysis

1. **Кратковременный сетевой сплит:** 43-секундный разрыв линка спровоцировал автоматическую переконфигурацию репликации между удаленными ЦОД.
2. **Несоответствие конфигурации Orchestrator архитектуре приложения:** Orchestrator имел право назначать primary-серверы в удаленном ЦОД. Приложение не рассчитано на кросс-региональные задержки (cross-country latency).
3. **Разрыв транзакций записи (Split-brain risk):** В момент потери связи старый master в East Coast содержал несколько секунд незареплицированных транзакций. Новый master в West Coast начал принимать свежие записи. Безопасный автоматический откат назад стал невозможен без риска потери клиентских данных.
4. **Медленное восстановление из бэкапов:** Скачивание терабайтов дампов из облачного хранилища заняло критически много времени из-за сетевых ограничений канала.
5. **Нелинейная деградация репликации:** Отставание реплик чтения под реальной нагрузкой росло по степенной зависимости. Чтение устаревших данных приводило к миганию контента на сайте.

---

#### 5. Resolution
Инженеры выбрали стратегию приоритета сохранности данных перед скоростью восстановления доступности платформы.

1. Остановили генерацию новых очередей задач (вебхуки, Pages).
2. Развернули синхронизацию недостающих бинарных логов (binlog) между East и West.
3. Ускорили наполнение новых реплик, переключив поток данных с внешнего объектного хранилища на прямое копирование с «живых» нод Западного побережья.
4. Ввели резервные облачные инстансы read-реплик для снижения утилизации CPU на чтении.
5. Завершили вычитку отложенных логов и вернули мастер-ноды на исходную локацию.
6. Разобрали 5 млн отложенных событий, вручную пропатчив TTL обработчика.
